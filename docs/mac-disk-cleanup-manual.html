Mac 容量そうじマニュアル

ターミナルで「調べて → 減らす」手順 ／ 2026-08-30 作成

このマニュアルでできること
Mac の空き容量が足りなくなったとき、何が容量を食っているかを自分で調べて、安全なものだけを消せるようになります。

2026-08-30 の実作業では、この手順で空きが 16GB → 197GB まで回復しました。PC の初期化は不要でした。

準備：ターミナルを開く

  1. Finder を開く
  2. 上のメニューから 「移動」→「ユーティリティ」
  3. 「ターミナル」 をダブルクリック

黒い文字だけの画面が出れば準備完了です。以降、枠の中の文字をコピーして貼り付け、Enter を押すだけです。

結論を先に知りたい方へ
原因を調べずにすぐ減らしたい場合は、「かんたん版：1行で終わらせる」の項だけ使えば十分です。

1今どれくらい空いているか調べる

df -h /System/Volumes/Data

結果の Avail の列が「空き容量」です。

Filesystem      Size    Used   Avail Capacity
/dev/disk3s1   460Gi   226Gi   197Gi    54%
                               ↑ここが空き
空き容量状態
50GB 以上問題なし。そうじ不要
20〜50GBそろそろ。時間があるときに
20GB 未満要そうじ。アプリの動作が不安定になる

2どこが大きいか調べる

「大きい入れ物を開けて、中でまた大きいものを探す」を繰り返します。これがコツです。

2-1. まずホームフォルダ全体

du -sh ~/* 2>/dev/null | sort -hr | head -10

たいていは Library が突出して大きく出ます。次はその中を見ます。

2-2. Library の中

du -sh ~/Library/* 2>/dev/null | sort -hr | head -12

2-3. さらにその中

大きかったフォルダの名前を、そのまま次のコマンドに入れて掘り下げます。

du -sh ~/Library/Caches/* 2>/dev/null | sort -hr | head -10
du -sh ~/Library/Application\ Support/* 2>/dev/null | sort -hr | head -10
コマンドの意味
du -shフォルダの大きさを見やすい単位で表示
sort -hr大きい順に並べる
head -10上位10件だけ表示
2>/dev/null権限がなくて読めない分のエラーを隠す
この段階では何も消えません。調べるだけのコマンドなので、安心して実行できます。

3アプリの「抜け殻」を探す

アプリを消しても、設定やキャッシュのフォルダは残り続けます。本体が無いのにデータだけ残っているものは、消して問題ありません。

ls /Applications
du -sh ~/Library/Application\ Support/* 2>/dev/null | sort -hr | head -30

2つの結果を見比べ、アプリ一覧に無い名前のフォルダが抜け殻です。

実例：Zoom、Postman、Genspark、CleanMyMac、Android Studio のデータが残っていました（合計約 0.5GB）。

4消す

消していいもの（消えても作り直されるキャッシュ）

# Adobe のキャッシュ ← 毎回ここが一番大きい（実測 138GB）
rm -rf ~/Library/Caches/Adobe
rm -rf ~/Library/Application\ Support/Adobe/Common/Media\ Cache*

# Chrome のキャッシュ（履歴やパスワードではない）
rm -rf ~/Library/Caches/Google/Chrome

# Xcode 関連
rm -rf ~/Library/Developer/Xcode/DerivedData
rm -rf ~/Library/Developer/Xcode/Archives
rm -rf ~/Library/Developer/Xcode/iOS\ DeviceSupport
rm -rf ~/Library/Developer/CoreSimulator/Caches
rm -rf ~/Library/Caches/CocoaPods
xcrun simctl delete unavailable

# ゴミ箱
rm -rf ~/.Trash/*

使っていないアプリ本体

du -sh /Applications/* 2>/dev/null | sort -hr | head -20

旧バージョンが残っていることがあります（例：Cinema 4D の 2025 と 2026 が両方ある）。消すときは：

sudo rm -rf /Applications/アプリ名
sudo を使うときの注意
Mac のログインパスワードを聞かれます。打っても画面には何も表示されません（●すら出ません）。これは正常です。そのまま入力して Enter を押してください。

OS アップデートの残骸

sudo rm -rf /Users/Shared/*Relocated\ Items*

容量は小さい（数MB）ですが、フォルダが大量に並ぶので見た目が整理されます。

かんたん版：1行で終わらせる

調べる工程を飛ばして、安全なものだけまとめて消します。これをコピーして貼り付け、Enter を押すだけです。

rm -rf ~/Library/Caches/Adobe ~/Library/Application\ Support/Adobe/Common/Media\ Cache* ~/Library/Caches/Google/Chrome ~/Library/Caches/CocoaPods ~/Library/Developer/Xcode/DerivedData ~/Library/Developer/Xcode/Archives ~/Library/Developer/Xcode/iOS\ DeviceSupport ~/Library/Developer/CoreSimulator/Caches ~/.Trash/* ; xcrun simctl delete unavailable ; df -h /System/Volumes/Data

最後に空き容量が表示されます。パスワードは不要です。

実行の目安は半年〜1年に1回。溜まる原因はほぼ Adobe のキャッシュなので、それ以上の頻度では意味がありません。

消してはいけない場所

場所理由
~/Library/Application Support/Google/Chromeブックマーク・保存パスワード。Chrome の設定画面からしか減らさない
~/Library/Containers/com.apple.Notes「メモ」の中身そのもの
~/Library/Mailメール本体
~/Library/MetadataSpotlight の検索索引。消しても再作成されるだけで、数時間 Mac が重くなる
~/Library/Application Support/AdobeAdobe 本体が使用中。消していいのは ~/Library/Caches/Adobe の方
~/Library/CloudStorage/Google ドライブの入口（次の項参照）
/Library, /SystemmacOS 本体。消すと起動しなくなる
迷ったら消さない。キャッシュは「消えても作り直される」ものだけです。名前に Cache が付いていないフォルダは、原則そのままにしてください。

まぎらわしいケース：Google ドライブ

du で見ると ~/Library/CloudStorage が 18GB などと表示されますが、設定が「ストリーミング」なら実体はクラウド上にあり、Mac のディスクは使っていません。

実際の使用量はこちらで確認します。

du -sh ~/Library/Application\ Support/Google/DriveFS
結果意味
1GB 前後正常。CloudStorage の数字は無視してよい
10GB 超キャッシュが溜まっている。Google ドライブの設定を確認

うまくいかないとき

表示されたメッセージ意味と対処
Permission denied
Directory not empty		ファイルの持ち主がシステムのため消せない。コマンドの先頭に sudo を付けて実行し直す
no matches foundエラーではありません。「もう存在しない＝すでに消えている」という意味
No such file or directoryそのフォルダが元から無い。無視してよい
パスワードを打っても
何も表示されない		正常です。そのまま入力して Enter
空き容量が増えないゴミ箱に入っただけの可能性。Finder のゴミ箱を空にする
